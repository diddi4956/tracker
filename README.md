# Tracker

일상 기록을 비교 가능한 데이터로 바꾸는 개인 트래킹 앱입니다.

## 해결하려는 문제
일반적인 불렛저널을 쓰거나 다이어리를 적으면 원인을 파악하기 위해 대조를 하기위해 많은 시간이 걸림. 직접 트래킹을 한다고 하더라도 월이 넘어가면 한번에 트래킹을 하지 못하고, 다른 요소와 비교하기 위하여 멀리잇는거를 가져오기도 힘들고 추이를 한번에 들여다보기도 힘듦. 그래서 이런것들을 해결하고자 데이터들을 특정 그래프로 바꿔주는 앱을 만든건데…그러고보니 이거 그냥 난 엑셀을 만든건가…기능이 정해진 엑셀정도…

## 어려웠던 문제와 해결 과정
- 컨디션 기록의 다대다 관계 : 하나의 컨디션 기록에 여러 환경 태그가 연결되고, 동일한 태그가 여러 기록에 사용될 수 있어 중간 관계 테이블을 구성했습니다. 날짜·컨디션·태그를 한 화면에서 보여주기 위해 각각의 조회 결과를 DTO로 받은 뒤 ViewModel에서 recordId 기준으로 그룹화해 화면 모델로 조합했습니다.

- 지출 중복 처리와 단가 : 처음에는 날짜·아이템·서브카테고리가 같으면 수량을 합쳤지만, 같은 날 같은 아이템을 서로 다른 단가로 구매한 경우 기존 단가로 합산되는 오류가 발생했습니다. 복합 고유 인덱스에 unitPrice를 추가하고 중복 조회 조건을 변경해, 단가가 같을 때만 수량을 합치도록 수정했습니다. 기존 데이터를 유지하기 위해 Room Migration도 작성했습니다.

- 기록과 트래킹 화면의 데이터 구조 : DB 구조를 화면에 직접 노출하지 않고, DAO의 범용 조회 결과를 ViewModel에서 일별·카테고리별·항목별 데이터로 조합했습니다. 같은 조회 함수를 여러 트래킹 기능에서 재사용할 수 있도록 복잡한 단일 쿼리보다 작은 조회와 화면 모델 조합을 선택했습니다.

## 주요 설계 결정
컨디션 tag를 definition이 아닌 record에 연결
체크되지 않은 기록은 별도 false행 대신 record부재로 표현
습관을 프로젝트와 definition으로 분리
프로젝트 기간을 기준으로 추적 범위 표현(트래킹페이지)
지출 카테고리를 고정해 입력 시 판단 비용 축소
dao는 범용 조회를 담당하고 viewModel이 화면 데이터를 조합
서로 다른 단가는 별도 지출 기록으로 저장
빈도 순으로 자주 사용하는 컨디션을 먼저 노출
실제 앱 사용 후 발견한 문제를 db Migration으로 수정

## 현재 한계와 향후 개선점
트래킹 화면의 정보 밀도가 높아 처음 사용하는 사람이 이해하기 어려움
트래킹 목적과 그래프 해석 방법을 안내하는 설명 부족
습관 프로젝트 전체에는 기간을 지정할 수 있지만 개별 습관에는 별도 기간을 지정할 수 없음
지출 카테고리가 고정되어 사용자의 생활 방식에 맞게 확장하기 어려움
기록 항목이 많아질수록 수동 입력 비용이 커짐
자동 테스트가 부족함
회전이나 프로세스 재생성 시 일부 팝업의 로컬 입력 상태가 사라질 수 있음

향후개선:
영수증 OCR을 이용한 지출 자동 입력
기존 아이템과 새 입력의 유사도 판단
AI를 이용한 카테고리·습관·컨디션 기록 정리 보조
트래킹 결과를 설명하는 온보딩과 가이드
UI 컴포넌트와 정보 구조 개선
개별 습관 기간 설정
rememberSaveable 또는 ViewModel을 이용한 입력 초안 보존
단위·통합 테스트 추가
